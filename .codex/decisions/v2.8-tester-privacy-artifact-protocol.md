# 2026-06-24 - Tester Privacy And Artifact Sharing Protocol

- Status: approved
- Decision owner: Bryant
- Decision: External testers should follow a privacy-first artifact sharing protocol. Synthetic or cleared assets are preferred. Confidential client files, tokens, passwords, full Figma links, file keys, signed URLs, private account screens, raw logs, broad filesystem listings, and full private package folders should not be shared by default. Diagnostics may be shared only for synthetic/cleared tests or when Bryant explicitly asks after a failure.
- Context: Crate tester feedback will often need evidence such as screenshots, screen recordings, package output inventories, package folders, and optional `Crate Diagnostics/crate-provenance.json`. These artifacts can accidentally contain client names, private paths, local usernames, Figma URLs, tokens, signed URLs, or confidential visuals.
- Rationale: Real designer workflows are valuable, but tester privacy and client confidentiality must be protected before the first tester group. A clear artifact protocol prevents well-intentioned testers from sending entire private packages or recordings with sensitive account screens.
- Implications: Tester onboarding, feedback forms, QA prompts, and support follow-ups must ask for redacted or synthetic artifacts first. Diagnostics stay off by default and should not be requested casually. Package output folders can be shared only when assets are synthetic, cleared, or explicitly approved.
- Non-goals: This decision does not change app diagnostics behavior, package contents, logging, code, release state, crate-web, or entitlement logic.
- Applies to: closed beta tester onboarding, tester feedback intake, artifact collection, screen recording guidance, diagnostics handling, QA synthesis, and bug triage.
- Does not apply to: Jenna internal QA with approved fixtures, local-only package inspection where no artifact leaves the tester's machine, or later explicit Bryant-approved private artifact review.
