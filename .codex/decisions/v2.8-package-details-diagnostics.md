## 2026-05-24 - Package Details And Optional Diagnostics

- Status: approved
- Decision owner: Bryant
- Decision: Provenance is an internal architecture and intelligence layer. It should not be the primary designer-facing language in Crate. Designer-facing package review should use terms such as Package Details, Included Files, File Sources, Needs Review, Why included, Extracted from, Linked from, and Used in. Raw `crate-provenance.json` output should be optional diagnostics, not a visible package-root file by default.
- Context: `v2.8.0-qa.1` is an internal QA prerelease. PowerPoint artifact inspection showed unexpected JPEGs came from inside the saved PowerPoint file under `ppt/media`, so package behavior was likely correct, but the explanation layer was not clear enough for designer-facing review.
- Rationale: Crate is for graphic designers and creative professionals. Designers need simple, trustworthy package explanation without learning internal graph terminology. Provenance should power package explanation, warnings, and review confidence behind the scenes.
- Implications: Final public `v2.8.0` should keep the default UX simple and seamless. Package Details should be optional/collapsed and controlled from Settings. User-facing copy should avoid provenance, evidence graph, nodes, edges, and confidence model unless the surface is explicitly internal or diagnostic. Diagnostic JSON, when enabled, should be written to a clearly named diagnostics location, likely `Crate Diagnostics/crate-provenance.json`, with privacy redaction still required.
- Non-goals: This decision does not implement settings, UI, package output behavior, parser behavior, or runtime diagnostics. It does not remove the internal provenance model or the need for evidence-backed package explanations.
- Applies to: v2.8.0 product UX, package review language, diagnostic JSON export behavior, QA/release notes, future Package Details work, and future diagnostics settings work.
- Does not apply to: Internal architecture names, test fixtures, developer-only docs, provenance helper code, or runtime behavior before an implementation PR changes it.
- Related PRs: Pending docs/product-decision PR.

- Supersedes: The package-root default implied by the earlier v2.8.0 architecture draft. It refines, but does not remove, the prior decision that `crate-provenance.json` is partial and package-relevant for now.
- Superseded by: None.
