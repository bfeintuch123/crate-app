# Decision: Crate Thread Orchestration Source Of Truth

Date: 2026-06-29

## Decision

For Crate work, this Codex thread is Bryant's source of truth and command center.

When a Crate task requires a fresh Codex thread, a Figma-specific thread, a QA thread, or another handoff thread, Codex should create or message that thread directly when the thread-management tools are available. Codex should not default to giving Bryant a prompt to manually paste into another thread.

## Expected Behavior

- Codex maintains the active Crate state in the repo docs and daily ledger.
- Codex uses thread tools directly when exposed, such as creating a new thread, sending a handoff prompt, or continuing a scoped Crate subthread.
- Bryant should only be asked to paste a prompt when thread tools are unavailable or blocked.
- If tool exposure fails, Codex should say so clearly and provide the fallback prompt.
- Any spawned or messaged Crate thread must follow the same repo, privacy, release, and package-engine guardrails as the current thread.

## Guardrails

- Do not create final public release threads, release/build/signing/notarization threads, or deploy/site mutation threads unless Bryant explicitly approves that scope.
- Do not hand off secrets, tokens, full Figma URLs with sensitive keys, signed URLs, raw logs, or unrelated private paths.
- Keep the current thread as the source of truth by updating:
  - `.codex/state/current-workstream.md`
  - `.codex/state/daily-crate-ledger.md`
  - relevant `docs/crate/` daily or decision files

## Reason

Bryant wants Crate coordination to become increasingly automatic. Codex should reduce manual copy/paste work and act as the durable orchestrator for Crate implementation, QA, Figma, release-gate, and tester-prep workflows.
