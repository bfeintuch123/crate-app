# 2026-06-24 - Figma Guidance Lives Primarily On get-crate.com

- Status: approved
- Decision owner: Bryant
- Decision: Detailed Figma support guidance should live primarily on get-crate.com, not as heavy explanatory copy inside the Crate app.
- Context: qa24 through qa41 validated that Figma Current Page Only works when the file is in an accessible Pro/team workspace and the user has valid Figma API access. QA also showed that Figma failures can come from Starter/Drafts location, plan/seat limits, file permissions, prototype-only links, API rate limits, or token setup confusion.
- Rationale: Figma behavior requires education about account plan, workspace/file location, per-project links, personal access tokens, Current Page Only, Entire File, and rate limits. That explanation belongs on the public site or docs where users can read it before setup and support can link to it. The app should stay focused on the immediate action and avoid becoming a dense Figma API explainer.
- Implications: get-crate.com should eventually include a clear Figma requirements/troubleshooting section. The app should keep concise operational copy only, such as token connection, paste Figma link, Current Page Only default, Entire File opt-in, and privacy-safe failure states that direct users to learn more.
- Non-goals: This decision does not update crate-web, deploy get-crate.com, change app code, change Figma API behavior, change Figma entitlement requirements, or create final public release copy.
- Applies to: UI/UX redesign, tester onboarding, public documentation, future release notes, support copy, and Figma troubleshooting.
- Does not apply to: internal QA-only prompts, code fixes for Figma parser/fetch behavior, or emergency in-app failure copy required for a bug fix.
