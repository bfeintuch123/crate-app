# 2026-06-24 - Closed Beta Tester Package Quota

- Status: approved
- Decision owner: Bryant
- Decision: Closed beta testers should receive an expanded monthly package quota, but not unlimited packaging. The default closed-beta tester quota should be 25 packages per month.
- Context: qa41 validated that both normal project packages and Quick Package count against `usage.packagesThisMonth`, and Bryant is preparing a small real-tester group before public `v2.8.0`.
- Rationale: Testers need more room than the public free limit to exercise real workflows, retries, diagnostics, and multi-app tests. Unlimited usage would weaken the product model and reduce useful usage-signal during beta. A 25-package cap is high enough for serious testing and low enough to preserve metering.
- Implications: Tester builds, tester onboarding, quota copy, Settings/footer usage display, and upgrade-limit messaging should be designed around a closed-beta package cap of 25 per month. Public/free quota remains 10 packages per month unless Bryant changes it later.
- Non-goals: This decision does not implement entitlement logic, change current app code, change public pricing, grant unlimited pro access, mutate dependencies, update crate-web, or alter release state.
- Applies to: closed beta tester planning, UI/UX redesign copy, tester onboarding, quota/upgrade UX, and future beta build requirements.
- Does not apply to: internal Jenna QA resets, current qa41 app behavior, paid/pro entitlement policy, or final public pricing.
- Related PRs: PR #110, which fixed Quick Package quota increments and quota-limit blocking.
- Related issues: none recorded.
- Related playbooks: `crate-tester-intake.md`, `crate-manual-qa-matrix.md`, `crate-decision-log.md`, `crate-qa-results-synthesizer.md`.

- Superseded by: none.
- Evidence: Bryant said testers should not have unlimited limits, but should have more than normal, around 15 to 25; Codex recommended 25 and Bryant approved proceeding with that policy.
