# Decision: Redesign Should Stay Close To Existing Crate

Date: 2026-06-27

## Decision

The macOS redesign should revert toward the simple Crate app structure that already exists, using the new visual layout without introducing extra product concepts or renamed state systems that make the app feel more complex.

The sidebar destination formerly considered as `Files` should be labeled:

- `Current Project`

Reason:

- `Files` sounds like a global file browser.
- `Projects` already exists as a section.
- `Current Project` accurately describes the selected/active project workspace, including watched files, needs-save items, Figma link state, Package Review, Package Complete, and Package Details.

## Implementation Guidance

- Keep current Crate app behavior and mental model.
- Use the new design language as a visual refresh, not as a product expansion.
- Avoid new terminology unless it directly maps to existing Crate behavior.
- Do not add Wispr Flow/productivity concepts.
- Do not create new app sections beyond what the current Crate app needs.
- Preserve the qa41 package engine and supported workflow states.

## Preferred Simple Navigation

- Home
- Projects
- Current Project
- Quick Package, either as a prominent action or lightweight route
- Settings
- Help

## Update: Remove Home

Bryant and Jenna decided to remove `Home`.

Final preferred navigation:

- `Projects`
- `Current Project`
- `Quick Package`
- `Settings`
- `Help`

Default landing behavior:

- If projects exist, land on `Projects`.
- If no projects exist, land on `Projects` with an empty state.
- `Current Project` is the selected/active project workspace.

Reason:

- Crate does not need a homepage/dashboard right now.
- Home was introducing extra dashboard/activity-feed complexity.
- The redesign should feel like the current Crate app with a cleaner macOS layout, not a new product model.

If no project is selected, `Current Project` should show a simple empty state:

```text
No project selected
Choose a project or start a new one.
```
