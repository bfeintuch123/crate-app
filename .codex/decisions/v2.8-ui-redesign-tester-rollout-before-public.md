# 2026-06-24 - UI Redesign And Tester Rollout Before Public v2.8.0

- Status: approved
- Decision owner: Bryant
- Decision: Crate should not proceed directly from qa41 engineering validation to final public `v2.8.0`. The next phase is Jenna's full macOS UI/UX redesign, followed by a small real-tester group, then final public release consideration.
- Context: qa24 through qa41 validated the packaging engine across Illustrator, InDesign, Photoshop/PSD, PowerPoint, Keynote, Figma, Quick Package, diagnostics, quota, package-output exclusions, and privacy checks. Bryant clarified that public release should come after redesign and tester feedback, not immediately after QA synthesis.
- Rationale: The packaging core is strong enough to become the engineering baseline, but tester trust and public readiness depend on a polished native app experience, clear Figma guidance, better review/refresh clarity, and real designer feedback.
- Implications: Future Codex sessions should not route directly to final public release execution from qa41. They should use the tester-readiness brief and redesign workstream first. Release gates remain useful, but final public release mutation requires a later explicit Bryant approval after tester rollout.
- Non-goals: This decision does not change app behavior, packaging logic, quota behavior, dependencies, build scripts, signing, notarization, crate-web, get-crate.com, or public release state.
- Applies to: `v2.8.0` planning, tester rollout, UI/UX redesign, QA synthesis, release readiness routing, and future handoffs.
- Does not apply to: internal QA prerelease builds, narrow bug-fix PRs, or docs-only tester prep that Bryant explicitly scopes.
