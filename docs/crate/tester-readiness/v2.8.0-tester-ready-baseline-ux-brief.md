## Remaining UX/Design Issues For Jenna

These are redesign inputs, not app-code release blockers by themselves.

### Core App Shell

- Make Crate feel like a polished native macOS app, not a QA harness.
- Clarify the primary modes:
  - watched project
  - Quick Package
  - package review
  - package result
  - settings and diagnostics
- Make empty state action obvious after clearing projects.
- Keep old or paused projects from visually competing with the active workflow.

### Project Watch State

- Show when Crate is watching, scanning, cooling down, or waiting for a save.
- Show a privacy-safe "last checked" or "last refreshed" signal.
- Consider a visible "Refresh" or "Check now" action for user confidence.
- If local state has updated but the visible list has not, the UI should refresh without requiring project reselection, relaunch, or incidental interaction.

### Package Review

- Review should match the user's mental model of what will be packaged.
- For PSD and parser-derived dependencies, make it clearer that package-time dependencies will be gathered even if they were not visible as top-level project rows earlier.
- Avoid provenance jargon in the primary review surface.
- Use friendly trust copy:
  - included files
  - gathered linked assets
  - extracted media
  - needs review
  - excluded unrelated files

### Package Complete And Package Details

- Package Complete should clearly state where the output was written.
- Desktop default for Quick Package is accepted by Bryant.
- Quick Package should still count against quota, which qa41 validates.
- Package Details should be designer-facing and concise:
  - files included
  - gathered files
  - extracted media
  - needs review
  - diagnostics included or not included

### Diagnostics

- Diagnostics should stay off by default.
- Settings should explain diagnostics as support/debugging output.
- When enabled, diagnostics belong under `Crate Diagnostics/crate-provenance.json`.
- The UI should not imply diagnostics are needed for normal packaging.

### Figma

- Keep detailed Figma requirements and troubleshooting on get-crate.com, not as heavy explanatory app copy.
- Website guidance should make the two Figma concepts unmistakable:
  - global Figma personal access token
  - per-project Figma file/page link
- Current Page Only should remain default.
- Entire File should remain explicit opt-in.
- Website guidance should explain that reliable Figma packaging needs appropriate plan, seat, file access, and workspace/file location.
- App copy should stay lightweight and operational:
  - connect Figma token
  - paste Figma file/page link
  - choose Current Page Only or Entire File
  - show a privacy-safe failure state
- If the app links to guidance, use a simple "Learn more" path to get-crate.com.
- App warnings should stay concise and privacy-safe for:
  - page lock unresolved
  - file cannot be read
  - rate-limited
  - token invalid or disconnected
- Do not expose full Figma URLs, file keys, signed URLs, or token values.

### Quota And Upgrade

- Show the current package count in a place users can understand.
- Make it clear that normal package and Quick Package both count.
- At limit, preserve the existing no-output quota block behavior.
- The upgrade prompt should feel like a product path, not an error trap.
- Closed beta tester builds should show a 25-package monthly cap, not unlimited access.
- Suggested tester copy: `Beta package usage: 4 of 25 this month`.
- Suggested tester limit copy: `You've used all 25 beta packages this month`.

### Needs Save / Needs Review

- Unsaved live linked assets should be visibly pending and not package-ready.
- Copy like "Save to make package-ready" is good and should stay clear.
- Needs Review should explain what the user can do next without implying Crate is broken.

## Tester Scripts By Workflow

Each tester should run one or two assigned workflows, not the whole matrix unless Bryant explicitly wants a deep QA pass.

### Script 1 - Install, Launch, And First Package Confidence

Goal:

- Confirm install, launch, basic navigation, and first package confidence.

Steps:

1. Install the assigned Crate build.
2. Launch Crate.
3. Open Projects, Files, Settings, and Quick Package.
4. Create and cancel one test project.
5. Package one simple approved file through Quick Package.
6. Open the output folder.

Expected:

- App opens normally.
- Navigation works.
- Quick Package output is scoped to the selected file and its real dependencies.
- Package count increments by one.
- No unrelated Desktop, Downloads, package-output, diagnostics, or private files appear.

### Script 2 - Illustrator Saved And Unsaved Links

Goal:

- Validate Illustrator linked assets and no-save pending behavior.

Steps:

1. Start Crate watching before opening the Illustrator file.
2. Open an approved AI file with existing linked assets.
3. Place two or three new linked images.
4. First observe before save if testing no-save behavior.
5. Save with normal `Cmd+S` for package validation.
6. Package after Crate shows the expected files.

Expected:

- Unsaved new linked assets show as `Needs save` and are not package-ready.
- After save, package includes one AI plus existing and newly used linked assets.
- Downloaded but unused controls are excluded.
- No stale lane files or unrelated files appear.

### Script 3 - InDesign Mixed Existing + New Links

Goal:

- Validate current INDD, existing links, new links, and unused-download exclusion.

Steps:

1. Create or open an approved INDD with two existing linked images.
2. Start Crate watching.
3. Add three new linked images from a folder that also contains two unused controls.
4. Save with normal `Cmd+S`.
5. Package after Crate refreshes.

Expected:

- Package contains exactly one current INDD plus five linked images.
- The two unused controls are absent.
- No `_1.indd`, stale Illustrator files, package-output folders, diagnostics, or unrelated files appear.

### Script 4 - Photoshop / PSD Linked Smart Objects

Goal:

- Validate linked smart-object dependency capture.

Steps:

1. Create or open a PSD with two existing linked smart objects.
2. Start Crate watching.
3. Add three new linked smart objects from a folder with two unused controls.
4. Save with normal `Cmd+S`.
5. Package.

Expected:

- Package contains one PSD plus all five linked images.
- Unused controls are absent.
- Package Complete, Package Details, and disk output must be correct even if pre-package project rows show only the PSD.

### Script 5 - PowerPoint Mixed Media

Goal:

- Validate PPTX media extraction and unused-download exclusion.

Steps:

1. Create or open a PPTX with two existing inserted images.
2. Start Crate watching.
3. Insert three new images from a folder with two unused controls.
4. Save with normal `Cmd+S`.
5. Package.

Expected:

- Package contains one PPTX plus five extracted media files.
- Unused controls are absent.
- No duplicate `_1` extracted media appears unless each file is a distinct expected media item.
- No diagnostics unless diagnostics are enabled.

### Script 6 - Keynote Mixed Media

Goal:

- Validate Keynote media extraction after normal save.

Steps:

1. Create or open a Keynote file with two existing inserted images.
2. Start Crate watching.
3. Insert three new images from a folder with two unused controls.
4. Save with normal `Cmd+S`.
5. Do not close/reopen unless instructed.
6. Package.

Expected:

- Package contains one `.key` plus five expected media files.
- New media is included after normal save.
- Unused controls are absent.
- No stale lane files or package-output folders appear.

### Script 7 - Figma Current Page Only

Goal:

- Validate Figma Current Page Only with an accessible file.

Preconditions:

- Tester has a valid Figma personal access token in Crate Settings.
- Tester has a Pro/team workspace file they can access through the Figma API.
- Tester has a design/editor file/page link, not a prototype-only link.

Steps:

1. Open the approved Figma file and current page.
2. Copy a design/editor page-node link.
3. Create a Crate project and add the Figma link.
4. Keep Current Page Only as default.
5. Wait for assets to stage.
6. Package.

Expected:

- Page lock resolves to the expected page.
- Current-page assets stage and package.
- Other files/pages are not silently included.
- Token, full URL, file key, and signed URL are never exposed.

### Script 8 - Figma Entire File Optional

Goal:

- Validate explicit opt-in multi-page capture.

Steps:

1. Use an accessible multi-page Figma file.
2. Add the file link to Crate.
3. Explicitly select Entire File.
4. Package.

Expected:

- Entire File is opt-in, never default.
- Eligible assets across the file package.
- Unrelated Figma files, local files, tokens, URLs, and file keys are excluded.

### Script 9 - Multiple Apps Open With Unrelated Files

Goal:

- Test the privacy and scope boundary in a realistic messy desktop.

Steps:

1. Open the assigned source workflow.
2. Keep one unrelated creative app file open.
3. Keep unrelated Downloads/Desktop controls present.
4. Package only the assigned workflow.

Expected:

- Package includes only the assigned workflow source and dependencies.
- Unrelated open app files, downloaded-but-unused assets, package outputs, diagnostics, and stale project files are absent.

### Script 10 - Diagnostics And Package Details

Goal:

- Validate support artifact behavior.

Steps:

1. Run one normal project package with Diagnostics OFF.
2. Confirm no `Crate Diagnostics` folder and no root `crate-provenance.json`.
3. Turn Diagnostics ON.
4. Run one normal project package.
5. Turn Diagnostics OFF after test.

Expected:

- Diagnostics OFF produces no diagnostics.
- Diagnostics ON writes only `Crate Diagnostics/crate-provenance.json`.
- Diagnostics is not counted as a design asset.
- Package Details counts match the design files.
- Privacy checks remain clean.

## Tester Privacy And Artifact Protocol

Tester-facing short version:

```text
Please use synthetic or cleared files whenever possible. Do not send confidential client files, tokens, passwords, full Figma links, file keys, signed URLs, private account screens, raw logs, or broad filesystem listings. If Crate fails on private work, send a redacted screenshot or filename/count inventory first. Only share package outputs or diagnostics if the files are synthetic, cleared, or Bryant explicitly approves.
```

Allowed by default:

- Screenshots of Crate UI with private names blurred if needed.
- Screen recordings of the Crate workflow, if they avoid passwords, tokens, emails, messages, account settings, and confidential client panels.
- Package output folders only when assets are synthetic, tester-created, or explicitly cleared.
- Redacted file inventories for private work, such as filenames, counts, expected included files, expected excluded files, and missing/extra items.
- Crate version, macOS version, app workflow, expected behavior, actual behavior, and package counts.

Not allowed by default:

- Confidential client files.
- Full Figma URLs or Figma file keys.
- Figma/API tokens.
- Signed URLs.
- Passwords, passkeys, Keychain prompts, browser account screens, private messages, emails, or account settings.
- Raw logs, broad filesystem listings, or unrelated file trees.
- Full package folders containing private work unless Bryant explicitly approves.

Diagnostics rule:

- `Crate Diagnostics/crate-provenance.json` is allowed for synthetic or cleared test files.
- For private work, diagnostics should not be shared unless Bryant explicitly requests it after a failure.
- If diagnostics cannot be shared, collect a redacted summary instead:
  - Crate version
  - package counts
  - expected files present or missing
  - unexpected files included or excluded
  - warnings shown
  - whether any private values were redacted

Severity hints:

- Critical: private asset exposure, destructive file behavior, credential/token/signed URL exposure, install/security block.
- High: assigned workflow cannot package, wrong asset included, key expected asset missed.
- Medium: confusing UI likely to cause misuse, non-private package discrepancy, diagnostics/provenance mismatch.
- Low: copy/polish issue, tester setup confusion, expected limitation needing clearer wording.

## Risks Before Inviting Real Testers

### Product / UX Risk

- The current QA build is functionally strong but not the final Jenna-designed macOS app experience.
- Testers may judge the old UI instead of the packaging engine unless framed correctly.
- Package Review can under-show PSD linked dependencies even when final package output is correct.
- Visible UI refresh lag can reduce trust even when local state and package output are correct.

### Figma Risk

- Figma success depends on plan, seat, file access, and file location.
- Starter/Drafts or client files without adequate access can rate-limit or fail closed.
- Full guidance should live on get-crate.com and tester instructions, not as dense in-app copy.
- Tester instructions and public guidance must clearly distinguish:
  - Settings token
  - per-project Figma link
  - Current Page Only
  - Entire File

### Privacy Risk

- Real testers may use client assets or private folders by habit.
- Screen recordings can accidentally capture tokens, passwords, messages, private client names, or account panels.
- Artifact collection must default to synthetic, cleared, or redacted evidence.
- Diagnostics can include filenames or local paths and should only be collected under the approved diagnostics rule.

### Quota / Beta Operations Risk

- The 10-package quota now applies to Quick Package and normal package flows.
- Closed beta testers should receive 25 packages per month, not unlimited access.
- Testers can still hit quota during evaluation if they rerun many package scenarios.
- Bryant still needs to choose the implementation mechanism for beta entitlements or resets before the tester build.

### Support Load Risk

- Early testers will create mixed product, setup, and bug feedback.
- Without strict intake, Codex will waste time reconstructing context.
- Assign one workflow per tester session unless the goal is exploratory feedback.

### Dependency Risk

- One moderate `uuid` advisory remains from audit review.
- High audit gate passed during release-prep review.
- Do not force-upgrade dependency majors during tester rollout unless Bryant scopes a dependency remediation loop.
